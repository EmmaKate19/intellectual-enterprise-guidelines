## 1. PURPOSE

Define the Business OS — the operating mechanics that make the organisation run. This is the "how work happens" layer: projects, meetings, documentation, naming, file structures, AI workflows, SOPs, quality standards, and version control.

## 2. SCOPE — must define / produce

- [ ] Project lifecycle mechanics (how a project is opened, tracked, closed)
- [ ] Meeting structure (when, how, what is captured)
- [ ] Documentation standard (the Business OS's own writing rules — distinct from but aligned with the Charter's editorial standard)
- [ ] Naming conventions (files, projects, ventures, documents)
- [ ] File structures (where things live — integrates with Knowledge Architecture, Stage 05)
- [ ] AI workflows (how AIs are invoked, what they produce, where output lands)
- [ ] SOPs (standard operating procedures — the repeatable processes)
- [ ] Quality standards (day-to-day operational quality, distinct from the 6 quality gates)
- [ ] Version control (how every artefact is versioned and maintained)
