## 1. PURPOSE

Define how a new idea becomes reality inside the organisation. Every venture — whether it becomes a company, stays a project, or is archived — follows the same lifecycle. This stage codifies that lifecycle so execution is repeatable and founder-independent.

## 2. SCOPE — must define / produce

- [ ] The venture lifecycle (canonical, established intent): Idea → Research → Validation → Prototype → Pilot → Business → Scale → Legacy
- [ ] Definition of each stage (what "done" looks like at each gate)
- [ ] Stage-gate criteria (what must be true to advance / halt / kill an idea)
- [ ] When an idea stays a project vs becomes a business (ties to Governance, Stage 04)
- [ ] Knowledge contribution rule (how a venture feeds learnings back to the single knowledge source, Stage 05)
- [ ] Brand assignment (how a venture receives its brand identity, Stage 07)
- [ ] AI involvement (which AI roles support which lifecycle stages — forward reference to Stage 09)
- [ ] Failure / archive protocol (what happens to killed ventures — knowledge is retained)

## 4. CONSTRAINTS

- The lifecycle is **established intent** — ratify it, do not redesign it.
- Must honour the founder's energy constraint — the framework must allow ventures to progress without founder presence at every gate.
- The clinic (from the prior GPT chat) is a **project, not a division** — use it as a worked example if useful, but do not resurrect the superseded 5-division model.
